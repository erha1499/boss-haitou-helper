# BOSS 海投助手

在 [BOSS 直聘](https://www.zhipin.com/) 的职位列表页上批量筛选岗位并自动发起沟通的浏览器用户脚本。单个 `.user.js` 文件，装进 Tampermonkey、脚本猫等脚本管理器就能用。

## 功能

- **求职向导**：选身份（实习 / 校招 / 社招）、方向、技术栈，一键生成整套筛选规则，不用自己写关键词
- **岗位类型**：按实习、校招/应届、社招（可细到 1-3 年等年限）、经验不限/未标明筛选，综合卡片标签、职位名和职位描述判断
- **两层筛选**：先按职位卡片上的职位名、工作地、公司、薪资粗筛，再打开详情，按职位描述和招聘者信息细筛
- **招聘者过滤**：按活跃状态（在线、今日活跃…）过滤，也可以只投指定职位的招聘者，比如只投 HR
- **每日目标**：设定今天累计投多少次，到量自动停止；遇到 BOSS 的 150 次上限也会停
- **多账号统计**：按账号分别记录今日和累计投递次数，同一浏览器同一时间只跑一个投递任务
- **投递历史**：按日期查看投过哪些公司，可以一键拉黑公司
- **实时预览**：改筛选规则时，用当前页的岗位实时预览会收集多少个、每个关键词命中多少个，并提示误伤；点提示里的岗位名可直接定位到该岗位
- **页面自检**：开始投递前检查能否读出职位列表，读不出职位名时不启动；投递中连续 3 个岗位卡在同一步（详情加载超时、找不到沟通按钮、点了沟通却没确认成功）时自动停止，避免 BOSS 改版后白跑或多投
- **配置分享**：筛选配置可以复制成文本发给别人，对方导入后直接使用，导入前能预览改动，也能撤销

## 安装

1. 安装任意一个脚本管理器：
   - [Tampermonkey（油猴）](https://www.tampermonkey.net/)：支持 Chrome、Edge、Firefox
   - [脚本猫 ScriptCat](https://scriptcat.org/)：支持 Chrome、Edge、Firefox，界面是中文
2. 点击安装脚本：[zdl改版-BOSS海投助手.user.js](https://github.com/erha1499/boss-haitou-helper/raw/main/zdl%E6%94%B9%E7%89%88-BOSS%E6%B5%B7%E6%8A%95%E5%8A%A9%E6%89%8B.user.js)，在弹出的安装页面点「安装」

脚本会自动检查更新，也可以在脚本管理器里手动「检查更新」。

需要较新版本的 Chrome 或 Edge，脚本用到了浏览器的 Web Locks API。

## 使用

1. 登录 BOSS 直聘，点顶部导航的「职位」，进入职位列表页（`zhipin.com/web/geek/jobs`）
   - 在其他页面（比如首页），右上角会出现「海投助手已就绪」卡片，点按钮就能跳过去
2. 首次打开会有新手引导，跟着走一遍就行
3. 在 BOSS 页面上只选城市（搜索词可以不填），**不要用 BOSS 自带的求职类型、经验、职位类型等筛选**：这些标签很多招聘方没填准，开了会漏掉大量岗位，比如职位名不写“实习”、按日薪计算、详情里才说可转正的实习岗。岗位越全越好，交给脚本的规则来筛
4. 点面板里的「筛选设置」。第一次使用、还没有规则时，点右上角的「求职向导」（或提示条里的「打开求职向导」），选好身份、方向和技术栈后点「预览改动」→「应用到规则」，快速得到一套基础规则；之后在筛选设置里逐项微调
5. 填写「今日目标」，点「开始投递」

面板默认固定显示。取消标题栏的图钉后，点击页面其他位置会把面板收起成小圆点，点圆点即可展开。

每次投递结束，日志会汇总本次投递和跳过的数量，以及各条规则跳过了多少个岗位，方便判断哪条规则过严。已经沟通过的岗位会被记住，下次直接跳过。

## 求职向导

给第一次使用、不熟悉规则的人：在「筛选设置」右上角点「求职向导」，回答几个选择题，脚本生成一套基础规则，写进筛选设置里对应的位置，之后可以逐项微调。

| 选项 | 生成什么 |
|---|---|
| ① 你在找什么 | 岗位类型：实习 / 校招·应届 / 社招（可限定经验年限），可选“也投没写明类型的岗位” |
| ② 想做什么方向 | 职位名「包含任一」：选中方向的常见写法；职位名「排除」：**没选中的方向**的特征词，比如只选“后端”会自动排除前端、测试、算法、客户端、嵌入式、运维、游戏、安全等。全栈、AI 应用和后端天然重叠，选它们时不会排除后端 |
| ③ 用什么技术栈 | 职位名「包含任一」加上技术栈名（如“Java开发”）；详情「包含任一」：技术栈相关词，比如 Java → `java\|spring*\|mybatis\|微服务` |
| ④ 其他 | 最低月薪、可面议、只投 HR、只投 3 天内活跃的招聘者、排除销售/客服/运营等非技术岗 |

- 可选方向：后端、全栈、AI应用/Agent、前端、测试、数据/大数据、算法、客户端/移动端、嵌入式/硬件、运维/DevOps、游戏、安全；算法方向覆盖大模型、CV、NLP、推荐/搜索、多模态、强化学习、数据挖掘等写法
- 可选技术栈：Java、Python、Go、C/C++、JS/TS、PHP、深度学习框架（PyTorch / TensorFlow / CUDA 等）
- 应用前会列出所有改动，应用后可以在底部「撤销上次替换」
- 向导只改上面这几项；**排除公司、工作地、详情排除词和今日目标保持不变**，适合放你自己的补充规则（比如届别）
- 向导会记住上次的选项，想换方向时打开向导改选，再应用一次即可

## 筛选规则

| 分组 | 规则 | 说明 |
|---|---|---|
| 岗位类型 | 岗位类型 | 实习 / 校招·应届 / 社招 / 经验不限·未标明，多选 |
| | 社招经验要求 | 勾选社招时生效：1年以内 / 1-3年 / 3-5年 / 5年以上 / 未写年限 |
| 职位列表粗筛 | 必须包含 / 包含任一 / 排除 | 匹配职位名 |
| | 工作地 | 包含任一，留空不限 |
| | 排除公司 | 公司名命中即跳过 |
| | 薪资范围 | 填最低、最高月薪（K），留空表示不限；日薪按每月 24 天折算。勾选「可面议」时，薪资写“面议”的岗位也会收集 |
| 职位详情细筛 | 排除 / 必须包含 / 包含任一 | 匹配职位描述、标签和职位名，打开详情后判断 |
| 招聘者筛选 | 活跃状态 | 只投勾选的状态 |
| | 只投这些招聘者 | 招聘者职位命中任一才投，留空不限，比如 `hr*`、`招聘`、`人事` |

猎头岗位默认跳过。

### 岗位类型怎么判断

BOSS 的经验标签只有“在校生、应届生、经验不限、1年以内、1-3年……”，没有“实习”，所以脚本综合三处信息：

1. **卡片和详情头部的标签**：`在校/应届` → 校招/应届，`经验不限` → 经验不限，`1-3年` 等 → 社招对应年限，`4天/周` → 实习；`6个月` 在没有写年限时也当作实习
2. **职位名和薪资**：含“实习/intern”、或薪资按天计算（如 `200-300元/天`） → 实习；含“校招、应届、管培、2027届、秋招、春招” → 校招/应届
3. **职位描述**（打开详情后）：“要求3年以上工作经验” → 社招 3 年；“实习期、可转正、转正机会、每周至少4天” → 实习；“应届毕业生、2027届” → 校招/应届；“社招” → 社招

几条规则：

- 实习岗的经验一栏常写“在校/应届”，有实习信号时按实习处理
- 写明了年限要求时按社招处理，取各处要求里最高的年限。比如卡片写“经验不限”、描述里写“要求3年以上工作经验”，按社招 3-5 年处理
- 只是加分项的不算要求：“有2年以上银行项目经验者优先”不会被当成社招
- 说的是候选人经历、或者带否定的不算：“1年以上实习经验”“不接受实习生”“不设实习期”“不要求3年经验”
- 正式岗的“试用期表现优秀可转正”不会被当成实习；“每周5天”这类作息也不算实习信号
- 卡片上什么都没写、描述里也看不出来的，归入“经验不限/未标明”
- 卡片上写明年限的，在列表阶段就能排除；其余打开详情后再判断，日志会写明依据，比如 `岗位类型"社招·3-5年"不在投递范围（详情：要求「3年以上Java开发经验」…）`

职位描述里 BOSS 会插入隐藏的干扰文字（比如“现场<kanzhun>面试”），脚本判断前会先去掉，所以 `现场.试` 这类关键词能正常命中。

有了岗位类型后，不用再在关键词里写 `社招`、`\d年.{1,5}工作经验`、`不.{0,3}实习` 这类规则。

### 检查规则有没有误伤

- **实时预览**：打开「筛选设置」，顶部会用当前页已加载的岗位试跑粗筛，显示“当前页 N 个岗位，会收集 M 个”，改规则后立即更新。每个职位名、工作地、公司关键词旁边会显示它在当前页命中的岗位数；如果某个排除词也挡掉了命中包含词的岗位（比如排除“应用”挡掉了“AI应用开发”），这个词会标黄并给出例子。点「明细」可以看到每个岗位会不会被收集、原因是什么，点某一行会在页面上定位到这个岗位
- **日志原文**：详情页因排除词、招聘者职位被跳过时，日志会附上命中的那段原文，比如 `命中排除词"不.{0,3}实习"（…本岗位「不限实习」时长）`，一眼就能看出是不是误伤

### 关键词写法

- **英文按整词匹配**：`java` 不会匹配 JavaScript，`rag` 不会匹配 storage；可以匹配复数，`agent` 能匹配 agents
- **前缀匹配**：末尾加 `*`，比如 `spring*` 匹配 SpringBoot，`ai*` 匹配 AIGC；和 `|` 一起用也可以，比如 `hr*|招聘|人事`
- **多种写法**：用 `|` 隔开，比如 `前端|客户端`
- **正则**：关键词按正则表达式处理，比如 `\d年.{1,5}工作经验`、`不.{0,3}实习`；写错的正则按普通文字匹配
- 不区分大小写

## 数据存储

所有配置、投递次数和历史都存在当前浏览器的 localStorage 里，不会上传到任何服务器。清除 zhipin.com 的网站数据会一并清空这些记录。

## 注意事项

- 自动投递有被平台限制的风险，请合理设置每日目标，后果自负
- BOSS 直聘改版后，页面结构可能变化，导致脚本失效。脚本会尽量自检并停下来，日志里出现「页面检查异常」时欢迎到 [Issues](https://github.com/erha1499/boss-haitou-helper/issues) 反馈
- 仅供学习交流，请勿用于商业用途

## 开发

源码在 `src/` 下按模块拆开，用 [Rollup](https://rollupjs.org/) 打包成仓库根目录的单个 `.user.js`（脚本管理器从这个文件检查更新，所以构建结果也要提交）。需要 Node.js 20 以上。

```bash
npm install
npm run build   # 生成 zdl改版-BOSS海投助手.user.js
npm test        # 单元测试，同时检查 .user.js 是否已用最新源码构建
```

| 目录 / 文件 | 内容 |
|---|---|
| `src/meta.js` | 脚本头（版本号、更新地址等），发版时改这里的 `@version` |
| `src/rules/` | 筛选规则：关键词匹配、薪资、岗位类型判断、粗筛、求职向导。不依赖页面和存储，单元测试覆盖这里 |
| `src/boss/selectors.js` | 脚本用到的 BOSS 页面选择器和按钮文字，BOSS 改版后先改这里 |
| `src/boss/self-check.js` | 页面自检 |
| `src/core.js` | 投递流程：滚动加载、粗筛、打开详情细筛、点沟通 |
| `src/ui.js`、`src/preview.js`、`src/styles.js` | 面板、设置、实时预览和样式 |
| `src/delivery.js`、`src/contacted.js`、`src/settings-store.js`、`src/state.js` | 账号与投递计数、已沟通记录、配置导入导出、运行状态 |
| `test/` | 单元测试（`node --test`） |

改判断规则时，先在 `test/` 里加一条能复现问题的用例，再改规则。
